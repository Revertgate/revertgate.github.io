A GitHub check for AI-written pull requests

Merge AI pull requests with proof, not hope.

Revertgate reverts the PR's code and reruns your tests. If they still pass, the tests don't cover the change, and the PR is blocked. It also catches skipped, deleted and weakened tests, and CI that's been switched off.

An AI reviewer gives you an opinion. Revertgate runs your tests.

Coding agents are good at making CI green, and sometimes they do it by changing the tests rather than the code. Revertgate checks the evidence itself. No LLM is involved, so the same PR always gets the same verdict.

01 · REVERT

Do the tests catch the change?

Revertgate puts the PR's code back to the base version, keeps the PR's tests, and runs them. They have to fail. If they still pass, they never touched the change.

02 · PER FILE

Which files are untested?

When a PR touches several files, Revertgate reverts each one alone and names any file no test notices.

03 · DIFF

Was anything weakened?

New skips and .onlys, deleted tests, net loss of assertions, exact matchers swapped for toBeTruthy(), suppressions, swallowed errors.

04 · GATE

Was the gate switched off?

continue-on-error, --passWithNoTests, removed test steps, a changed test script. Revertgate reads its own config from the base branch, so a PR can't relax it.

Why now

In a Linux Foundation survey, 64% of open-source maintainers said AI-assisted submissions have made their reviews take longer. Revertgate turns "did the agent actually test this?" into a check you can require before a merge.

Without Revertgate

Green CI on an agent's PR tells you the tests passed. It doesn't tell you they test anything, or that the agent didn't edit them to pass.

With Revertgate

Every PR states what was proven: "reverted billing.ts, 3 tests failed". Reviewers read the diff knowing the tests mean something.

Install in two minutes

Run revertgate init in your repo, or add this workflow. It works with any test command: pytest, Jest, Vitest, cargo, go test, PHPUnit, RSpec.

name: Revertgate
on:
  pull_request:
    types: [opened, synchronize, reopened, labeled, unlabeled]
permissions:
  contents: read
  pull-requests: write
jobs:
  revertgate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
        with:
          fetch-depth: 0
      - run: npm ci            # whatever your tests need
      - uses: revertgate/revertgate@v0
        with:
          license-key: ${{ secrets.REVERTGATE_LICENSE_KEY }}  # private repos only

Questions

Does my code leave my CI?

No. Revertgate is a single binary that runs in your own GitHub Actions runner. For private repos it sends one request with your licence key to check it's valid, and nothing else.

What if a finding is wrong?

A maintainer adds the revertgate-override label. Revertgate still reports the findings but lets the PR merge, so the override is visible in the PR history. Rules can also be set to warn or off in .revertgate.toml.

Does it only work on AI-written PRs?

It works on any PR. It's built for the ways agents game tests, but a human who deletes a failing test gets the same answer.

Doesn't the revert check slow CI down?

It runs your suite twice (once on the PR, once reverted), plus once per file for PRs that touch up to 8 code files. The per-file limit is configurable.

What are its limits?

A flaky suite can fake either answer, a build error with the change reverted counts as "caught", and tests that live inside a source file are reverted along with it. Revertgate says which check ran, so you can judge it.
