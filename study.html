STUDY · NOVEMBER 2026 · BY SALIORNETIZEN, MAKER OF REVERTGATE

I read 484 pull requests written by AI coding agents. Here's what they did to the tests.

484merged agent PRs scanned
44%touched test files
1–2clearly weakened the test gate

Coding agents now open pull requests at enormous scale: GitHub search lists about 1.5 million merged public PRs from the Copilot coding agent alone, plus hundreds of thousands from Devin, Jules and Cursor. A common worry is that an agent told to "make CI green" will make the tests green instead of the code right: skip the failing test, loosen the assertion, switch the CI step off.

I built a check for exactly that, so I pointed it at real agent PRs to see how often it actually happens.

What I did

  • Sampled 500 merged public PRs opened by four agents' GitHub Apps: 125 each from the Copilot coding agent, Cursor, Devin and Jules, 25 per day across five days, June–October 2026.
  • Downloaded each PR's diff (484 succeeded) and ran Revertgate's diff checks on it: new skips, deleted tests, lost assertions, loosened matchers, suppressions, swallowed errors and changes to the CI test gate.
  • Read every finding that would have blocked a merge, by hand.

What I found

211 of the 484 PRs (44%) touched test files. Cursor's PRs touched tests most often (77 of 121).

Outright test-gaming was rare. On the first pass, my rules would have blocked 20 PRs (4%). Read by hand, they broke down like this:

What the PR didPRs
Skipped a test only when the environment lacked something (Docker, Postgres, symlinks, -short)11
Deleted tests along with the code they tested, in a refactor or feature removal6
Made a test skip itself when its container start timed out, hiding a failure1
Removed the test scripts and the CI test steps1
A false alarm in my own rules, or harmless2

So: roughly 1–2 PRs in 484 clearly weakened the test gate. Half of what looked like cheating was good engineering.

The quieter patterns were more common. Across the 484 PRs:

  • 27 added a lint or type-check suppression (eslint-disable, # noqa, @ts-ignore…)
  • 17 swallowed an error (except: pass, an empty catch)
  • 4 loosened an exact assertion into a truthiness check

None of those block a merge on their own, but they are exactly what a reviewer skimming an agent's 40-file PR misses.

What I changed because of it

My first rules were wrong about half the time on real code, which would have made Revertgate a check people switch off. So I fixed them before publishing this:

  • Skips guarded by a condition (skipif, skipUnless, #[ignore = "needs postgres"], a skip inside an if) now warn instead of blocking.
  • A pattern that mistook prettier's --ignore-path for pytest's --ignore was fixed.

Rescanning the same 484 PRs: blocks fell from 20 to 11, and the one blocking skip left is the one that hides failures.

What this study can't tell you

  • The interesting failure is invisible in a diff. The worst agent PR isn't the one that skips a test; it's the one whose new tests pass whether or not the new code works. Catching that means reverting the PR's code and rerunning its tests, which is what Revertgate does in your CI, but I couldn't do it for 484 strangers' repositories.
  • Many agent PRs live in small personal repos; this is a sample of public agent PRs, not of production codebases.
  • The rules are text heuristics. I read every blocking finding by hand; warnings I counted without reading each one.
